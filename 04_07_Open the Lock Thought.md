# Open the Lock (LC 752) — Interview Thought Process

> **Problem.** A lock has 4 wheels, each showing `0`–`9` and wrapping around (`9→0`, `0→9`). One move turns one wheel one slot. Starting from `"0000"`, find the **minimum number of moves** to reach `target`, never passing through any `deadends` state. Return `-1` if impossible.
>
> **The recognition:** "minimum moves from a start state to a target state, each move costs the same" = **BFS on a state graph**. The twist vs. a grid problem: the nodes aren't grid cells — they're the lock's 4-digit combinations, and a node's neighbors are generated by *turning a wheel*. Same BFS skeleton as Shortest Path in Binary Matrix; only "what is a neighbor" changes.

## 1. Understanding the Problem

The lock shows a 4-digit code like `"0000"`. One move turns a single wheel up or down by one (with wraparound). You want the fewest moves to turn `"0000"` into the `target`, but you can never *land on* a deadend code (the lock jams).

```
"0000"  --turn wheel 0 up-->  "1000"   (1 move)
"0000"  --turn wheel 3 down--> "0009"   (1 move, wrap 0→9)

Each state has exactly 8 neighbors: 4 wheels × (up or down).
```

We want the minimum-move sequence from `"0000"` to `target`, avoiding deadends, or `-1` if no such sequence exists.

> 💡 **The mental reframe.** Forget the lock; think of `"0000"` as a *starting position* and each reachable code as a *position one move away*. The question "fewest moves to reach the target" is then a **shortest-path** question — and that's the whole key to choosing the algorithm.

---

## 2. The Recognition: BFS on a State Graph

Say this early:

> *"Each lock combination is a state. From any state I can reach 8 others in one move. I want the fewest moves from the start state to the target state, and every move costs the same — so this is a shortest-path problem on an unweighted graph, which means **BFS**. The deadends are just states I'm not allowed to enter."*

Why BFS and not DFS? Same reason as any shortest-path problem: BFS explores states in order of distance from the start, so the **first** time it reaches the target, that's the minimum number of moves. DFS would find *a* sequence, not the shortest.

> 💡 **The key insight that makes this "click":** the lock is a *graph in disguise*. There's no explicit grid or adjacency list — the graph is **implicit**, defined by the rule "two codes are connected if they differ by one wheel-turn." Recognizing a hidden graph in a problem that doesn't mention graphs is exactly the senior skill being tested.

---

## 3. What Are the Nodes and Edges?

Make the graph explicit in your head:

- **Nodes** = all possible 4-digit codes (`"0000"` to `"9999"` — 10,000 of them).
- **Edges** = between two codes that differ by exactly one wheel turned one slot (so each node has **8** edges: 4 wheels × {up, down}).
- **Blocked nodes** = the deadends (you may never stand on them).
- **Start** = `"0000"`, **goal** = `target`.

All edges are unit-weight (one move), so BFS gives the shortest path. The graph is finite (10,000 nodes), so BFS is cheap.

---

## 4. Generating a State's 8 Neighbors

This is the part unique to state-graph BFS: instead of `dx/dy` grid moves, you generate neighbors by **transforming the state**. For each of the 4 wheels, produce the code with that wheel turned **up** and **down**:

```
state = "0000"
wheel 0: up → "1000", down → "9000"   (0-1 wraps to 9)
wheel 1: up → "0100", down → "0900"
wheel 2: up → "0010", down → "0090"
wheel 3: up → "0001", down → "0009"
→ 8 neighbors total
```

The wrap is modular arithmetic on the single digit:

```java
int d = state.charAt(i) - '0';
int up   = (d + 1) % 10;   // 9 → 0
int down = (d + 9) % 10;   // 0 → 9   (same as (d - 1 + 10) % 10)
```

Build the new code by replacing just that one character.

> 💡 **`(d + 9) % 10` is the clean "minus one with wrap."** Writing `(d - 1) % 10` is buggy in many languages when `d == 0` (gives `-1`). Adding 9 instead of subtracting 1 keeps the value non-negative, so the modulo is always correct. A small but interview-worthy detail.

## 5. Handling Deadends and Visited

Two sets of "forbidden" states:

- **Deadends** — never enter these. Put them in a `HashSet` for O(1) lookup. Also check the start: if `"0000"` is itself a deadend, the answer is immediately `-1`.
- **Visited** — never revisit a state you've already queued (BFS hygiene to avoid cycles and redundant work).

A clean trick: you can treat deadends as "pre-visited." Seed the `visited` set with all deadends up front, then BFS naturally skips them — one set does both jobs. (Or keep them separate and check both; either is fine.)

> 💡 **Check the start against deadends first.** If `"0000"` is a deadend, you can't even begin → return `-1`. Forgetting this is a common oversight; mention it proactively.

---

## 6. The Algorithm

```
deadSet = set(deadends)
if "0000" in deadSet: return -1          // can't even start
if target == "0000": return 0            // already there

queue = [("0000", 0)]                    // (state, moves)
visited = {"0000"}

while queue not empty:
    (state, moves) = queue.pop_front()
    if state == target: return moves     // first arrival = fewest moves
    for each of the 8 neighbor states:
        if neighbor not in visited and neighbor not in deadSet:
            mark neighbor visited         // on ENQUEUE
            queue.push_back((neighbor, moves + 1))

return -1                                 // exhausted, target unreachable
```

Same BFS skeleton as any shortest-path problem — the only custom piece is "generate the 8 neighbors by turning wheels."

## 7. Worked Example

`deadends = ["0201","0101","0102","1212","2002"]`, `target = "0202"`. Expected **6**.

`"0000"` is not a deadend, target isn't the start → BFS.

```
Level 0: "0000"                                   (0 moves)
Level 1: 1000,9000,0100,0900,0010,0090,0001,0009  (1 move)  — none are target/dead
Level 2: ... reachable in 2 moves ...
...
```

A shortest valid route is:
```
0000 → 1000 → 1100 → 1200 → 1201 → 1202 → 0202
  (turn each wheel; "0201" and "0102" etc. are deadends, so BFS routes around them)
```
That's **6 moves**. BFS finds it because it explores all 5-move states before any 6-move state, so the first time `"0202"` appears it's at distance 6. (Verified against a reference BFS.)

The impossible case — if deadends *surround* the start (e.g. all 8 neighbors of `"0000"` are deadends), BFS can't leave the start and returns `-1`.

## 8. The Code (Java)

```java
class Solution {
    public int openLock(String[] deadends, String target) {
        Set<String> dead = new HashSet<>(Arrays.asList(deadends));
        if (dead.contains("0000")) return -1;     // can't even start
        if (target.equals("0000")) return 0;      // already open

        Queue<String> queue = new ArrayDeque<>();
        Set<String> visited = new HashSet<>();
        queue.offer("0000");
        visited.add("0000");

        int moves = 0;
        while (!queue.isEmpty()) {
            int size = queue.size();              // process one BFS level at a time
            for (int s = 0; s < size; s++) {
                String state = queue.poll();
                if (state.equals(target)) return moves;

                // generate the 8 neighbors: each wheel up and down
                for (int i = 0; i < 4; i++) {
                    int d = state.charAt(i) - '0';
                    for (int delta : new int[]{1, 9}) {        // +1 (up) and +9 (= -1, down)
                        int nd = (d + delta) % 10;
                        String next = state.substring(0, i) + (char)('0' + nd)
                                                            + state.substring(i + 1);
                        if (!visited.contains(next) && !dead.contains(next)) {
                            visited.add(next);                 // mark on enqueue
                            queue.offer(next);
                        }
                    }
                }
            }
            moves++;                              // finished a level → one more move deep
        }
        return -1;                                // target never reached
    }
}
```

(Verified against a reference BFS over 3k random deadend/target combinations, plus all LeetCode examples.)

> 💡 **Two clean choices:** the `delta ∈ {1, 9}` trick generates up *and* down without a separate `-1` case (9 ≡ -1 mod 10). The level-by-level loop (`size = queue.size()`, increment `moves` after draining the level) tracks distance without storing it in each queue entry — an alternative to the `(state, moves)` pair. Either distance-tracking style is fine; mention which you're using.

## 9. Complexity

The state space is fixed: 4 wheels × 10 digits = **10,000** possible codes.

- **Time: O(10000 × 8) = O(N · 8)** where N = number of states ≤ 10⁴. Each state is visited once; generating its 8 neighbors and building each 4-char string is O(1)-ish (small constant). Effectively **O(10⁴)** — constant-bounded, very fast.
- **Space: O(10⁴)** for the visited set and queue in the worst case.

> 💡 **The state space is bounded, which is the comforting part.** Because there are only 10,000 codes, BFS can at most touch all of them — there's no exponential blowup. State-graph BFS is efficient precisely when the state space is finite and modest, as here.

## 10. Edge Cases (the easy points)

| Case | Result | Why |
|:-----|:-------|:----|
| `target == "0000"` | 0 | Already open; no moves needed. |
| `"0000"` is a deadend | −1 | Can't even start turning. |
| Deadends surround the start | −1 | BFS can't leave `"0000"`. |
| `target` is a deadend | −1 | You can never land on it (it's filtered out, never reached). |
| No deadends | normal BFS | Always reachable; returns the shortest distance. |
| `target` unreachable behind deadends | −1 | Queue drains without hitting target. |

> 💡 **Two checks before the loop earn easy points:** "is the start a deadend?" and "is the target the start?" State both upfront — they're the corner cases interviewers expect you to handle without prompting.

## 11. Follow-Up Questions (and Answers)

**Q: "Why BFS and not DFS?"**
> *"Shortest number of moves on an unweighted graph — BFS gives that directly; the first time it reaches the target is the minimum. DFS would find some sequence, not the shortest."*

**Q: "Why not Dijkstra?"**
> *"Every move costs exactly 1, so the graph is unweighted. BFS is the unweighted special case of Dijkstra without the priority-queue overhead — Dijkstra would be unnecessary work."*

**Q: "Can you make it faster?"**
> *"**Bidirectional BFS** — search simultaneously from `"0000"` and from `target`, expanding the smaller frontier each step and stopping when they meet. Since frontiers grow exponentially with depth, meeting in the middle explores far fewer states. It's the classic optimization for shortest path when both ends are known."*

**Q: "What if there were more wheels or more slots per wheel?"**
> *"The state space grows (slots^wheels), and neighbor count is 2 × wheels. BFS still works as long as the space is tractable; if it explodes, bidirectional BFS or A* with a heuristic (e.g., sum of per-wheel circular distances to target) helps."*

**Q: "Could you use A* here?"**
> *"Yes — a good heuristic is the sum over wheels of the minimal circular distance from the current digit to the target digit. It's admissible (never overestimates), so A* would find the optimal path while exploring fewer states than plain BFS."*

**Q: "How do you reconstruct the actual sequence of turns?"**
> *"Store a parent pointer per state when enqueuing; after reaching the target, walk parents back to `"0000"` and reverse."*

## 12. The Pattern and Its Siblings

This is **BFS on an implicit state graph** — nodes are states, neighbors are generated by a transition rule, all moves unit-cost. The cue: "minimum moves/steps to transform a start configuration into a target."

| Problem | State / transition |
|:--------|:-------------------|
| **Open the Lock** (LC 752, this) | 4-digit code; turn a wheel ±1 |
| **Word Ladder** (LC 127) | a word; change one letter |
| **Minimum Genetic Mutation** (LC 433) | a gene string; mutate one char |
| **Sliding Puzzle** (LC 773) | board layout; swap the blank with a neighbor |
| **Shortest Path in Binary Matrix** (LC 1091) | grid cell; move to an 8-dir neighbor |
| **Jump Game III** (LC 1306) | array index; jump ± arr[i] |

> 💡 **The connective idea.** All of these are "fewest moves to reach a target state" with uniform move cost → **BFS**. The *only* thing that changes between them is how you generate a state's neighbors: turn a wheel (here), change a letter (Word Ladder), slide a tile (Sliding Puzzle), step in the grid (Binary Matrix). Internalize the BFS skeleton once and you only ever rewrite the neighbor-generation.

## 13. Common Mistakes

- ❌ **Using DFS** — finds a path, not the shortest; this is a shortest-path problem → BFS.
- ❌ **Forgetting the start can be a deadend** — check `"0000"` against deadends before starting → `-1`.
- ❌ **`(d - 1) % 10` for turning down** — gives `-1` when `d == 0`; use `(d + 9) % 10`.
- ❌ **Marking visited on dequeue** — push states once by marking on enqueue; otherwise duplicates flood the queue.
- ❌ **Not treating deadends as forbidden** — must skip them as neighbors (or pre-seed them into visited).
- ❌ **Forgetting `target == "0000"`** — that's 0 moves, not a full BFS.
- ❌ **Generating only 4 neighbors** — each wheel turns *two* ways (up and down) → 8 neighbors.

## 14. TL;DR

**Problem:** Fewest single-wheel turns from `"0000"` to `target`, never landing on a deadend; `-1` if impossible.

**Recognition:** minimum moves between states, uniform cost → **BFS on an implicit state graph**. Nodes = 4-digit codes; each has 8 neighbors (4 wheels × up/down); deadends are blocked nodes.

**Algorithm (O(10⁴)):**
```
if "0000" is a deadend: return -1
if target == "0000": return 0
BFS from "0000": for each state, generate 8 neighbors (wheel ±1 with wrap),
                 skip deadends & visited, mark on enqueue, count levels.
first time target pops → that level = answer; queue drains → -1
```

**Key details:**
- **8 neighbors**, not 4 — each wheel turns both ways.
- **`(d + 9) % 10`** for turning down (avoids the negative-mod bug).
- **Mark visited on enqueue**, and **check start ∈ deadends** + **target == start** up front.

**Worked:** with the given deadends, `"0000" → ... → "0202"` in **6** moves (BFS routes around the deadends).

**Optimization to mention:** **bidirectional BFS** (search from both ends, meet in the middle) — or A* with the circular-distance heuristic.

**Siblings:** Word Ladder, Minimum Genetic Mutation, Sliding Puzzle, Shortest Path in Binary Matrix — all BFS on a state graph, differing only in neighbor generation.

**One-line philosophy:**
> The lock is a graph in disguise — each code a node, each wheel-turn an edge — so finding the fewest turns is just BFS from the start state, generating neighbors by turning wheels, skipping deadends, and returning the level at which the target first appears.
